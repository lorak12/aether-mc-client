# Status and setup

## Where to put ids and keys
All optional. Set them in `aether.config.json` inside the launcher's app data folder (Settings > About shows the path), or as environment variables. Restart the launcher after changing them.

| Setting | Env var | Enables |
|---|---|---|
| `azure_client_id` | `AETHER_AZURE_CLIENT_ID` | Microsoft sign-in. Browser sign-in also needs `http://localhost` as a "Mobile and desktop applications" redirect URI on the Azure app; the code flow works without it. |
| `curseforge_api_key` | `AETHER_CURSEFORGE_API_KEY` | CurseForge search, project pages, installs, updates and modpacks |
| `backend_url` | `AETHER_BACKEND_URL` | Friends, chat, presence, store, coins, news, banners, featured servers, online count; cosmetics and the badge in game |
| `manifest_public_key` | `AETHER_MANIFEST_PUBLIC_KEY` | Launcher update check and install, client jar updates (hex Ed25519 key matching `AETHER_MANIFEST_SEED`) |

Backend env: `AETHER_JWT_SECRET` (required in production), `AETHER_DB` (SQLite file, default `aether.db`), `AETHER_ADMIN_TOKEN`, `AETHER_MANIFEST_SEED` (32-byte Ed25519 seed, hex), `AETHER_PUBLIC_URL` (for checkout return pages), `AETHER_WELCOME_COINS`, `AETHER_ADMINS` (extra names with unlimited coins, comma separated; the built-in list is `backend/src/admins.ts`, currently `nakii14`), `AETHER_COSMETICS_DIR` (store art; defaults to the runtime's cosmetics folder), `PORT`. Payments: `AETHER_TEBEX_PUBLIC_TOKEN`, `AETHER_TEBEX_WEBHOOK_SECRET`, `AETHER_COIN_BUNDLES` (JSON: `[{"id":"<tebex package id>","coins":1000,"bonus":100,"price":"€4.99","best":true}]`); point the Tebex webhook at `<public url>/v1/webhooks/tebex`. Development only: `AETHER_ALLOW_OFFLINE=1` lets offline accounts sign in (refused when `NODE_ENV=production`).

Admin (Bearer `AETHER_ADMIN_TOKEN`): `PUT /v1/admin/feeds/news|banners|servers` replaces a feed (shapes in `backend/src/routes/feeds.ts`, example in `backend/seed/feeds.example.json`), `POST /v1/admin/coins {uuid, amount, label}`, `POST /v1/admin/grant`, `PUT /v1/admin/manifest/:channel` signs and publishes an update manifest (shape in `launcher/core/src/update.rs`).

## Built and tested

- `launcher/src-tauri` + `launcher/ui`: redesigned launcher (spec: `docs/superpowers/specs/2026-10-07-launcher-ui-redesign-design.md`). Top bar (app menu, back/forward, coins, Ctrl+K search, notifications, account switcher, live logs, window controls), left sidebar, friends sidebar, and the Home, Profiles (version groups, loader choice, profile settings with per-setting overrides), Content (Modrinth with filters/sort, install dialog, Shift quick install, dependency prompt, modpack to profile, project pages), Explore, Community, News, Store and coin shop pages. Everything is real (no preview data left): profiles and their settings, content from both providers, worlds/servers/gallery, launch/stop with crash reports, tray icon (hide to tray, comes back when the game exits), friends/chat/presence/store/coins/news/servers through the backend, update check and log sharing. Profile metadata and global settings moved from webview storage into `profile.json` / `settings.json` (migrated once on first start). UI tests: `cd launcher/ui && npm test`. Checked in a browser with `npm run dev` (dev mock, `src/devMock.ts`) and started as the desktop app; the full in-app click-through is on the checklist in `docs/LAUNCHER_TODO.md`.

Unit-tested (box UV checked against vanilla's ModelPart.Cube; sync against a fake backend); not yet verified in-game.

## Playing with the client
- In-game keys: **Right Shift** opens the hub; **Mods** opens the mod window. In the list layout, click a row to toggle it and the gear (or right-click) for its settings. In the card layout, click a card for its settings and its bottom bar to toggle it. Typing searches. "Edit HUD layout" opens the layout editor: drag to move, scroll to resize, right-click to reset, Esc when done. Default hotkeys: C zoom (scroll changes the level), V freelook, G fullbright.
- Cosmetics: **Right Shift**, then **Cosmetics** (header button or sidebar). Hover a card to try it on, click to equip, click again (or right-click) to take it off; drag the preview to turn it. Your own capes and models go in `<game dir>/config/aether/cosmetics` (see `cosmetics/README.md`).
- Config: `<game dir>/config/aether/config.json` (client-wide: menu key, main menu options, favorites, seen mods, mod data, cosmetics) plus one file per profile in `config/aether/profiles/<name>.json` (`"format": "aether-profile"`: name, icon, auto-switch servers, every mod's enabled/settings/HUD). Profile files can be shared: Export copies one to `config/aether/exports/`, Copy puts its JSON on the clipboard, and Import takes clipboard JSON or files dropped into `profiles/`. Older configs move their profiles into files on first load. It saves when the menu closes and when the game quits.
- Account switching in the main menu: the launcher passes `AETHER_ACCOUNTS_FILE` (names/uuids, no tokens). While the game runs the launcher also listens on a loopback-only port (`AETHER_SESSION_PORT`, guarded by the per-launch secret `AETHER_SESSION_KEY`): picking another account asks it for that account's session (it refreshes the Microsoft sign-in, makes the account the launcher's active one and emits `account-switched`), and `McSession` swaps it in without a restart (user, profile/skin, user API service, privileges, chat signing keys, reporting, telemetry; cosmetics sync signs in again). Without the port it falls back to `AETHER_RELAUNCH_FILE` (quit, the launcher relaunches as that account). Without the launcher, only the current account shows.
- Own skin: vanilla looks the signed-in player's profile up once at startup; when sessionserver times out you wear the default skin all session. `McSession.tick` retries the lookup with back-off (2 s to 2 min, 6 tries) and puts the result in place, so worlds joined afterwards show your skin.
- From the launcher: Fabric/Quilt profiles on a version in `launcher/core/src/runtime.rs` get `mods/aether-client.jar` installed at every Play when a matching jar exists. For the verified 26.1 family, build with `cd runtime && ./gradlew.bat :v26_1:build :v26_1_1:build :v26_1_2:build`. The launcher looks in `AETHER_RUNTIME_DIR`, then `<app data>/runtime/`, then this repo's `runtime/<adapter>/build/libs/`.
- Without the launcher: `cd runtime && ./gradlew.bat :v26_3:runClient` (or `:v1_21_11:runClient`) starts a dev client, or copy the built jar into any Fabric profile's `mods` folder.
- In-game smoke test: `./gradlew.bat :v26_3:runAutotest` (also available for `v1_21_11` and the 26.1 family). It joins `run/saves/AetherTest`, a disposable test world, then walks through the HUD, menu, settings, HUD editor, zoom, time/weather, fullbright, freelook and the world map, writes `run/screenshots/aether-*.png`, and quits. It never saves config.

## Running the launcher
- Standalone: `cd launcher/src-tauri && cargo tauri build --no-bundle`, then run `target/release/aether-launcher.exe`.
- Dev with hot reload: `cd launcher/src-tauri && cargo tauri dev`.
- Without an approved Azure app: account menu (top right) > "Add offline account" with any name. It uses a placeholder token, so it only works in singleplayer and on offline-mode servers.
- The release exe finds the client jar through this repo's `runtime/<adapter>/build/libs/` (a path compiled into the exe), so rebuild the runtime and click Play again. You don't need to rebuild the launcher.
- Azure app must: allow personal Microsoft accounts, have "Allow public client flows" = Yes, and be approved for Minecraft services (https://aka.ms/mce-reviewappid).

## Launching (built)
- Shared Minecraft settings (on by default, per-profile override): `options.txt` is merged key by key from `<data>/shared/options.txt` before each launch and back after the game exits, so video settings, keybinds and sound are the same in every profile. Resource pack lists stay per profile; versions before 1.13 share `shared/options-legacy.txt` (old key codes). The first launch seeds the shared copy from the most recently changed profile.
- Play: silent re-login from the keychain refresh token (stored in chunks; Windows caps secrets at 2560 bytes), Mojang Java runtime provisioning, Fabric/Quilt loader install, libraries/natives/assets, log4j config, spawn with output to `<profile>/logs/launcher-output.log`.
- Live check: `cargo test -p aether-core --test live prepare_and_boot -- --ignored --nocapture` (boots 1.21.11 Fabric by default with a placeholder session; `AETHER_TEST_PROFILES=1.21.11:fabric,1.8.9:vanilla`; `AETHER_TEST_EXTRA_MODS=<folder>` adds mod jars). When the Aether client is installed, the test also asserts that it loaded. Verified 1.21.11 and 26.3 (with a 16-mod set) on 2026-09-29.
- Forge / NeoForge profiles can't launch yet (their installers must be run).
