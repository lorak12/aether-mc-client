# Handoffs

- task 8 -> later tasks (goal-runner): the runtime/sandbox is gone by user request; verify with unit tests and `runAutotest`.
  Mods can be added to BuiltinMods freely (tests assert >= 32). Config is schema 2 (profiles). The menu key is `ModManager.menuKey`.
  26.3 autotest: SDL mouse buttons arrive a frame late; check them in a later step than you post them.
- task 9 -> 10-13: new adapter logic goes in runtime/mc-shared/src/main/java/gg/aether/mc (compiled per version); version
  differences go in each adapter's gg/aether/mc/Compat.java. Mixins stay per adapter (26.3 uses Hud + mc.gui.screen(), 1.21.11 Gui + mc.screen).
  26.3 moved entity types to EntityTypes, DisplayInfo.getTitle -> title(). Autotest logs every GameState value ("[autotest] state").
- task 13 -> later tasks: chat goes through McEvents.receive (ChatMessage + ChatReceive posted there). Global (non-profile) tables:
  use mods/GlobalTable with a Setting.Entries. Overrides.replaceNames + McEvents.replaceNames(Component) keep styles.
  One-shot hotkey actions: ChatMods.pressed(h). Shadow private MC methods as `@Shadow private ... { throw new AssertionError(); }`.
  No in-game runs this goal (user tests manually): verify every mixin target with javap (scratchpad jp.sh) before compiling.
- task 20 -> 18 and later (claude-cosmetics): cosmetics live in core gg.aether.core.cosmetics (ModManager.cosmetics(); loadout +
  toggles saved under "cosmetics" in config.json, global). Adapters: mc-shared McCosmetics (textures, cape swap in
  AvatarRenderer.extractRenderState, CosmeticLayer on every AvatarRenderer, badge via McRender.nameTag/tabName) + per adapter
  AvatarRendererMixin, LivingEntityRendererAccessor, Compat.cutoutNoCull. Starter assets are generated by
  cosmetics/StarterCosmetics.java (--preview renders them on a player for review); add new built-in ids to backend/src/catalog.ts.
  Skin layers / emotes for task 18 can hook the same AvatarRenderer mixin and the Cosmetics page preview (UiRenderer.player).
- task 20 follow-up (claude-cosmetics): wavy capes. core WavyCape builds the cape as a bent/rippled mesh (flat = vanilla's cape,
  unit-tested); McCosmetics.wavyCape(state) decides per render state, CosmeticLayer draws it and per-adapter CapeLayerMixin
  cancels vanilla's CapeLayer.submit for the same states. Anything else that draws capes should check McCosmetics.wavyCape.
- task 21 -> launcher/backend work (claude-launcher-ui): launcher/ui is restructured (api/, app/store.tsx, shell/, pages/<page>/, components/, lib/).
  Every call goes through `api` in ui/src/api/index.ts; mocked domains (coins, store, social, news, servers, worlds, screenshots,
  CurseForge) live in ui/src/api/mock and only need their function bodies swapped for real endpoints. UI-only profile data
  (kind, cover, description, builtinOnly, overrides, disabled) is in localStorage `aether.ui.profile.<id>` via `profileMeta`.
  Backend follow-ups are listed in docs/STATUS.md "Not built yet". `npm run dev` runs the whole UI in a browser on the devMock.
- task 22 -> anyone touching the in-game UI (claude-ingame-ui): every Aether screen is built on core `ui/Ui.java` (immediate-mode
  widgets, popups, scroll areas, focus) and `Theme`. Setting editors dispatch on `Setting.kind()`, so a new setting type needs a
  Kind plus a case in `Ui.control`. Mod icons/SERVER tab live in mods `BuiltinMods.decorate` (ICONS map is test-enforced for every
  mod). Profiles are `config/aether/profiles/<file>.json` via `ProfileFiles`; `ModManager.exportProfile/importProfile` give the
  JSON. The jar is NOT a resource pack (no Fabric API): put assets under mc-shared/src/main/resources and load them from the
  classpath (see `McUi.texture`, `McFonts`). Backend follow-ups: coins/announcements/promo are `MenuFeed.preview()`; Store and
  Chat are "coming soon" panels; emotes are a SOON tile on the hub.
- task 23 -> anyone touching the in-game UI (claude-ui-polish): icons are `core/ui/Icons` (SVG path strings on a 24x24 grid,
  "F " prefix = filled; preview them by rasterising `Icons.mask`); `Mod.icon()` is an icon name, not an item id. New renderer
  calls: `UiRenderer.pixelScale()` and tinted `image(..., tint)` (both adapters implement them). Clickable regions now carry a
  `Ui.Sound` (CLICK by default): use `ui.absorb(...)` for silent panel/popup backgrounds, `ui.hit(..., Sound, ...)` for others,
  `ui.tick(frac)` in drags. `Setting.Color.argb()` is chroma-aware; the picker edits `base()`. Accessibility moved from a mod to
  `ClientSettings` (applied to Overrides in `ModManager.tick`). Accounts: `McSession` (mc-shared) + per-adapter
  `MinecraftSessionAccessor`/`Compat.switchUser`; launcher side is `SessionBridge` in src-tauri/lib.rs.
- task 24 -> anyone touching the launcher (claude-launcher-finish): profile data lives in profile.json (format 2: `overrides`,
  `meta`, `loader_version`, `game_dir`) and settings.json; the UI never stores profile data in localStorage any more
  (app/migrate.ts moved it once). Content folders resolve through `ProfileStore::game_dir`, not `dir`. Tauri commands are split
  by area in src-tauri/src (profiles, content, files, accounts, game, online, shell). Every backend call goes through the
  `backend_call` command (it holds and refreshes the backend token); add backend routes under backend/src/routes. The browser
  dev mock (ui/src/devMock.ts) must get a handler for each new command. Store prices: epic 600 / legendary 1200 coins in
  backend/src/catalog.ts; the in-game wardrobe doesn't lock unowned items yet (see docs/LAUNCHER_TODO.md).
- task 25 -> anyone touching HUD widgets / the editor / cosmetics (claude-feedback): `UiRenderer.clip` is in the current push
  transform (GuiGraphics.enableScissor maps the rect through the pose), not screen space. `HudElement.resizable` widgets read
  `boxWidth()/boxHeight()` and call `natural(w, h)` before `resolve` (HudTextMod, TargetInfo, Scoreboard, compass do); others are
  scaled by the side handles. Saved colours are `ClientSettings.savedColors`, given to the picker via `Ui.palette`. 26.3 screens
  need `textInputManager().startTextInput(owner)` for character events. Cosmetics sync: `Cosmetics.synced` is the last agreed
  loadout (saved in config); `CosmeticsSync.reconcile` adopts the backend's loadout unless the player changed theirs since; the
  game sends `PUT /v1/me/loadout?lenient=1`. Launcher: `skin_url` command for heads; add new mutating commands to
  `LOGGED_COMMANDS` in src-tauri/lib.rs and a handler in devMock.ts.
- task 27 -> anyone touching input in mc-shared / task 26 (claude-feedback-2): only 26.3+ reads input through SDL; 26.1.2 and
  26.2 are still GLFW. Gate SDL translation (`SdlInput`) on `>=26.3`, API changes like `mc.gui.screen()` stay on `>=26.1`.
  Launcher: `accounts::session_for` caches Minecraft sessions for 4h (single-flight, `SESSIONS`) and `online::token` holds its
  lock across sign-in; don't release either lock before the refresh, login_with_xbox rate limits at a handful of calls.
  Note: v26_1_2 currently doesn't compile (task 26 in progress: Hud, getDeviceInfo, mainRenderTarget).
- task 27 -> anyone touching text fields (claude-feedback-2): `Ui.textField`/`searchBox` share `Ui.editable` (caret + selection
  in `Ui.caret/anchor`, sideways scroll in `viewStart`). Change a focused field's text through `ui.charTyped`, not `field.set`,
  or the caret goes stale. `Field.max()` caps typing; `selectNextField` now selects all instead of replace-on-type.
- task 28 -> anyone touching cosmetics / the wardrobe / coins (claude-shop): the Wardrobe page has Wardrobe and Shop
  tabs (`WardrobePage.Mode`; `ClientGui.openShop`, pages "shop"/"store", hub Shop tile, main menu `Host.store()`).
  Store state is `Cosmetics.shop()` (`Shop`: offers, coins, unlimited, buy/refresh on the sync worker via
  `CosmeticsSync.fetchStore/buy`, results through `Shop.poll()`). Admins with unlimited coins are listed in
  backend/src/admins.ts (+ `AETHER_ADMINS`); `/v1/me`, `/v1/store`, `/v1/store/buy` add `unlimited`, the launcher turns it
  into `Infinity` (`balanceOf`). Local cosmetics load through `LocalCosmetics` (pictures/JPG/GIF -> capes via `Images`,
  GIF/JPG model textures, OBJ models via `ObjModel` -> `CosmeticModel.Part.polys`, thumbnails via `Thumbnail`, cache in
  `<cosmetics>/.cache`, names starting with . or _ skipped). `Importer` copies picked files into a folder + cosmetic.json
  and writes the Blender kit (`_blender-kit`, ref_* objects ignored). File dialogs: `ClientHost.pickFiles` ->
  `Desktop.pickFiles` (PowerShell / osascript / zenity+kdialog), both McHosts. `MenuFeed.preview()` coins are -1 now.
- task 29 -> anyone touching cosmetics (claude-shop): published cosmetics live in the backend kv table via
  backend/src/custom.ts (`Customs`: /v1/admin/cosmetics POST/DELETE for admins, /v1/cosmetics/:id/bundle, merged into
  /v1/store, loadouts, grants and icons); clients mirror them into `<cosmetics>/.remote/<id>/` in
  `CosmeticsSync.syncPublished` and load them as shared (builtin=true) cosmetics. `Shop.admin()` = unlimited (same
  list). Blockbench import is `BbModel` (Blockbench space -> model: (-x, 24-y, z)); `CosmeticModel.Placement` is a live
  root transform around the geometry centre, `CosmeticModel.preset` adds flap/bob/spin/sway. The importer is `Draft`
  (staged in `<cosmetics>/_draft`, file names sanitised for the store) + `ui/CosmeticEditor`; `ImportPopup` only picks
  the file and writes the creator kit (`Importer.writeCreatorKit`). `UiRenderer.player(..., yaw, pitch)` tilts the
  preview (mc-shared only). The guide is docs/COSMETICS_GUIDE.md, packed into the jar by core/build.gradle.kts.
